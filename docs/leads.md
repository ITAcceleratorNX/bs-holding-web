# Интеграция форм с Bitrix24 — устройство

Настройка портала описана отдельно: [bitrix24.md](./bitrix24.md).
Здесь — как это устроено в коде и как добавить новую форму.

## Поток данных

```
Форма (useLeadForm)
   │  проверка полей, блокировка кнопки, submissionId
   ▼
POST /api/lead            ← браузер знает только этот адрес
   │
   ▼
server/lead-handler.js    ← единый серверный модуль
   │  origin → размер тела → ловушка для ботов → лимит частоты
   │  → повторная проверка полей → защита от дублей
   ▼
server/bitrix/mapper.js   → поля лида
   ▼
server/bitrix/client.js   → crm.lead.add (таймаут, повторы)
   ▼
Bitrix24
```

Успех показывается пользователю **только** после того, как портал вернул номер
лида. Любая ошибка оставляет форму в состоянии, из которого можно отправить
повторно, — с тем же `submissionId`, поэтому дубль не появится.

## Где что лежит

| Путь | Назначение |
| --- | --- |
| `src/lead/contract.js` | Проверка и нормализация заявки. **Изоморфный** — используется браузером и сервером |
| `src/lead/formCodes.js` | Реестр форм и построение темы лида |
| `src/lead/phone.js` | Казахстанский номер: маска, проверка, формат передачи |
| `src/lead/attribution.js` | UTM: сбор при входе, хранение 30 дней, первый и последний источник |
| `src/lead/analytics.js` | События `form_open`, `form_submit`, … в `dataLayer` |
| `src/lead/details.js` | Сборка данных квиза, планировки и расчёта |
| `src/lead/useLeadForm.js` | Общее поведение всех форм |
| `src/lead/submit.js` | Транспорт до `/api/lead` |
| `src/lead/whatsapp.js` | Ссылка в WhatsApp и вкладка, открытая до запроса |
| `src/components/lead/` | `LeadPopup`, `LeadHoneypot`, `PhoneLink` |
| `server/` | Серверный модуль. В браузерный бандл не попадает |
| `api/lead.js` | Точка входа Vercel — тонкий адаптер над `lead-handler.js` |
| `server/vite-plugin.js` | Тот же обработчик на `npm run dev` |

`server/lead-handler.js` не зависит от фреймворка: на входе объект запроса, на
выходе объект ответа. Переезд с Vercel на другой хостинг — это новый адаптер
на десяток строк, логика не меняется.

## Формы

Тринадцать форм из ТЗ и их коды — в `src/lead/formCodes.js`. Код формы уходит
в CRM и в аналитику, **менять его после запуска нельзя**.

## Как добавить новую форму

1. Добавьте запись в `FORM_CODES` (`src/lead/formCodes.js`).
2. В компоненте вызовите хук:

```jsx
const form = useLeadForm({
  formCode: 'my_new_form',
  city,
  project,
  ctaLocation: 'Блок «Ипотека»',
  details: () => buildDetails('context', [['my_field', 'Подпись в карточке', value]]),
});
```

3. Отрисуйте поля и кнопку:

```jsx
<input {...form.fields.name} placeholder="Ваше имя" />
{form.errors.name && <div className="form-error">{form.errors.name}</div>}
<input {...form.fields.phone} />
{form.errors.phone && <div className="form-error">{form.errors.phone}</div>}
<LeadHoneypot {...form.honeypotProps} />
{form.message && <div className="form-error">{form.message}</div>}
<button onClick={form.submit} disabled={form.isLoading}>
  {form.isLoading ? 'Отправка…' : 'Отправить'}
</button>
<div className="lead-policy">{CONSENT_POLICY}</div>
```

Сервер менять не нужно: новые значения из `details` попадут в комментарий лида
автоматически. Отдельное поле в CRM подключается переменной окружения — см.
[bitrix24.md, шаг 4](./bitrix24.md#шаг-4-пользовательские-поля-необязательно).

Если для формы нужен popup, возьмите `LeadPopup` и добавьте тексты
в `LEAD_FORM_PRESETS` (`src/data/leadForms.js`).

## Согласие на обработку данных

Хук поддерживает два режима:

- `implied` (по умолчанию) — согласие фиксируется по факту отправки, рядом
  с кнопкой обязателен текст `CONSENT_POLICY`;
- `explicit` — отдельная галочка; используется в калькуляторе рассрочки.

В обоих случаях в CRM уходят факт и дата согласия. Если юристы потребуют галочку
везде, достаточно передать `consentMode: 'explicit'` и отрисовать чекбокс.

## Аналитика

Все события уходят в `window.dataLayer`. Счётчики (GA4, Яндекс.Метрика)
подключаются через Google Tag Manager — код сайта при этом не меняется.
Имя и телефон в события не передаются: параметры проходят через белый список
в `src/lead/analytics.js`.

## Защита от дублей и спама

- Кнопка блокируется на время отправки, плюс отдельная защита от опережающего клика.
- Каждой заполненной форме присваивается `submissionId`; он сохраняется при повторе
  после ошибки, поэтому повторная отправка не создаёт второй лид.
- Одновременные запросы с одним `submissionId` ждут первый и получают его результат.
- Скрытое поле-ловушка и проверка «форма заполнена быстрее секунды» отсекают простых ботов.
- Лимит частоты по IP — `LEAD_RATE_LIMIT`.

> Защита от дублей и лимит частоты хранятся в памяти процесса. На Vercel это
> покрывает быстрые повторные клики (они попадают в один «тёплый» экземпляр
> функции), но не даёт глобальной гарантии на все экземпляры. Если такая
> гарантия понадобится, подключите общее хранилище — интерфейс `get/set/delete`
> для этого выделен в `server/ttl-map.js`.

## Локальная разработка

```bash
cp .env.example .env
```

Впишите `BITRIX_WEBHOOK_URL` и запустите `npm run dev` — `/api/lead` поднимется
тем же обработчиком, что и в проде. Без вебхука формы вернут понятную ошибку,
а в консоли сервера появится `config_invalid`.

Тесты:

```bash
npm test
```
