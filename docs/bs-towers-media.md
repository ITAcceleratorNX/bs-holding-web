# BS Towers — материалы страницы ЖК

Экспорт из Figma складывается в одну папку, дальше всё делает скрипт:

```bash
node scripts/prepare-bs-towers-images.mjs ~/Downloads/bs-towers
```

Он режет по пропорции слота, сжимает в WebP и раскладывает по
`public/images/bs-towers/`. Руками копировать ничего не нужно.

Скрипт делает три вещи, которые легко пропустить вручную:

- **отрезает пустые поля** — Figma оставляет чёрные полосы, если рендер не
  заполнил рамку (так было с `apartments`: 51px черноты справа);
- **не растягивает** — если исходник меньше слота, отдаёт родное разрешение в
  нужной пропорции вместо мыла;
- **обрезает белые поля вокруг чертежа** — иначе планировка болтается в центре
  карточки, теряя треть размера;
- **отклоняет маркетинговый лист планировки** — если вместо чертежа подсунуть
  лист с рендером здания, логотипом и QR-кодами, скрипт откажется его брать:
  ТЗ запрещает выводить QR-коды и рекламные надписи.

## Правила отбора кадров

- Только материалы BS Towers. Рендеры других ЖК на этой странице недопустимы —
  это ловит тест `src/data/bsTowers.test.js`.
- Берём «чистые» рендеры: без рекламных баннеров, сторис-рамок, подписей,
  логотипов поверх кадра, QR-кодов, плашек с ценами и телефонами.
- Формат `.webp`, качество 80–85. Планировки — тоже `.webp`, но экспорт из
  векторного листа (текст остаётся читаемым).
- Планировки — на белом фоне, все четыре разные. Повторять один лист в разных
  карточках нельзя.

## Точные размеры экспорта

Все слоты страницы, кроме планировок, обрезают кадр по `object-fit: cover`.
Колонка «пропорция» — это пропорция самого слота: если экспортировать в ней,
на ноутбуке (1440 px) кадр обрежется примерно на 12% по высоте, на большом
мониторе (1920 px) — сильнее. Поэтому **оставляйте запас сверху и снизу**
(небо над зданием, отмостку под ним) — по краям должно быть не жалко.

| Файл | Размер экспорта | Пропорция | Что на кадре |
|---|---|---|---|
| `hero.webp` | 2560×1600 | 16:10 | Первый экран: общий вид комплекса, горизонтально |
| `hero-mobile.webp` | 1200×2000 | 3:5 | Тот же кадр, вертикальный кроп (экраны ≤768 px) |
| `about.webp` | 2560×1433 | 1,79:1 | Три башни целиком (см. ниже — этот слот не режет кадр) |
| `feature-parking.webp` | 1200×1280 | 15:16 | Двор над паркингом (высокая плитка) |
| `feature-fitness.webp` | 1200×612 | 1,96:1 | Fitness Room |
| `feature-glazing.webp` | 1200×612 | 1,96:1 | Панорамное остекление / вид из окна |
| `location-map.webp` | 2400×1160 | 2,07:1 | Схема расположения в 40-м микрорайоне |
| `place-dina.webp` | 800×1140 | 0,7:1 | Гипермаркет Dina |
| `place-park.webp` | 800×1140 | 0,7:1 | Президентский парк |
| `place-museum.webp` | 800×1140 | 0,7:1 | Музей им. А. Кекилбаева |
| `architecture.webp` | 2400×1160 | 2,07:1 | Фасад крупно: АКП, клинкер, гранит |

Имена в таблице — это имена **исходников**, которые кладутся в папку выгрузки.
Планировки называются как в Figma (`plan-1r … plan-10r`); осмысленные имена
файлов на сайте (`plans/b2-3r-106.webp` — блок 2, 3 комнаты, 106 м²) скрипт
проставляет сам по таблице внутри себя.

Планировки выводятся по `object-fit: contain` на белой плашке — они не
обрезаются никогда, пропорция любая. Важно экспортировать **сам чертёж**, а не
маркетинговый лист целиком: на листе рендер здания, логотипы, QR-коды Whatsapp
и Instagram и пустые поля под цену — всё это ТЗ запрещает выводить, и скрипт
такой файл отклонит.

## Слот, который подстраивается под кадр

Блок «О жилом комплексе» — исключение: там важно показать здание целиком,
поэтому высота блока идёт от пропорции рендера, а не от фиксированных 420px.
Задаётся в `src/data/bsTowers.js`:

```js
image: `${IMG}/about.webp`,
imageRatio: '2560 / 1433',   // пропорция файла — кадр не режется вообще
```

При замене рендера на другой пропорции поменяйте `imageRatio` под новый размер
и заодно строку `about` в `SLOTS` внутри скрипта. Проверено на 390, 1440 и
1920px — обрезка 0% на всех ширинах.

Так можно сделать с любым слотом, где кадр важнее ритма страницы. Но не со
всеми сразу: фиксированные высоты как раз и держат вертикальный ритм.

## Если кадр обрезался не там

Не трогайте CSS. В `src/data/bsTowers.js` у слота есть поле `imagePosition` —
это значение CSS `object-position`:

```js
image: `${IMG}/about.webp`,
imagePosition: 'center 35%',   // поднять кадр: видно верх башен
```

`'center top'` — прижать к верху, `'center 65%'` — опустить.
Поле работает в hero, about, standards, location (карточки и карта),
architecture, yard, kids и apartments.

## Планировки: комнатность, площадь, цена

Источник данных — массив `BS_TOWERS_PLANS` в `src/data/bsTowers.js`.
Комнатность, площадь и блок сняты с самих листов планировок:

| Блок | Комнатность | Площадь | Исходник |
|---|---|---|---|
| 2 | 1 | 54,50 м² | `plan-4r` |
| 2 | 1 | 54,98 м² | `plan-9r` |
| 2 | 2 | 78,00 м² | `plan-5r` |
| 3 | 2 | 82,59 м² | `plan-10r` |
| 2 | 3 | 106,46 м² | `plan-1r` |
| 3 | 3 | 106,46 м² | `plan-6r` |
| 2 | 3 | 120,46 м² | `plan-3r` |
| 3 | 3 | 140,46 м² | `plan-8r` |
| 2 | 4 | 145,79 м² | `plan-2r` |
| 3 | 4 | 146,23 м² | `plan-7r` |

Две планировки на 106,46 м² — не дубль: это разные решения в блоках 2 и 3,
у них отличаются площади комнат. Номер в имени исходника (`plan-7r`) — это
порядковый номер листа, а не комнатность: `plan-7r` это 4-комнатная.

Цена выводится только вместе с `priceConfirmed: true`:

```js
{ id: 'bst-b2-1r-54', block: 'Блок 2', rooms: '1 комната', area: '54,50 м²',
  image: `${PLANS}/b2-1r-54.webp`, price: 'от 24 900 000 ₸', priceConfirmed: true },
```

Без этого флага `price` вырезается при сборке карточки — неподтверждённая цена
не попадёт на сайт, даже если её впишут по ошибке.

Планировок может стать больше: добавьте строку в `BS_TOWERS_PLANS` и слот в
`SLOTS` внутри скрипта. Сетка перестроится сама.

## После замены

```bash
npm test
```

Тест проверит, что все файлы реально лежат на диске, что все они из материалов
BS Towers, что ни один рендер не занимает два слота и что планировки не
повторяются. Если чего-то не хватает — тест назовёт файлы поимённо.

Старые заглушки `public/images/bs-towers/*.svg` (кроме `icon-*.svg` и
`card.svg`) после замены можно удалить — на них больше ничего не ссылается.
`card.svg` — карточка ЖК в каталоге на главной, это отдельная задача.
