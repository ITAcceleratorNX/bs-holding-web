# Подключение сайта к Bitrix24

Инструкция для того, кто настраивает интеграцию. Программировать ничего не нужно —
всё делается в интерфейсе Bitrix24 и в панели Vercel.

> **Про безопасность.** Пароль от аккаунта Bitrix24 нигде не понадобится: ни в коде,
> ни в репозитории, ни разработчику. Единственное, что нужно передать сайту, — это
> **вебхук**. Его вы создаёте сами и вставляете в настройки Vercel.

---

## Что такое вебхук

Вебхук — это длинная ссылка-ключ, по которой сайт получает право создавать лиды
в вашем Bitrix24. Примерно так:

```
https://bsholding.bitrix24.kz/rest/1/9k3l2m4n5p6q7r8s/
```

Правила простые:

- ссылку нельзя публиковать и пересылать в открытых чатах — по ней можно работать с вашей CRM;
- если ссылка утекла, её удаляют в Bitrix24 и создают новую (шаг 1), сайт при этом
  достаточно передеплоить с новым значением;
- в код сайта она не попадает — только в переменные окружения Vercel.

---

## Шаг 1. Создать вебхук в Bitrix24

1. Войдите в Bitrix24 под администратором.
2. В левом меню откройте **Приложения** → **Разработчикам**.
   (В некоторых версиях портала: **Приложения** → **Ещё** → **Разработчикам**.)
3. Выберите **Другое** → **Входящий вебхук**.
4. В поле **Название** впишите понятное имя, например `Сайт BS Holding — заявки`.
5. В списке **Настройки прав** отметьте галочкой **CRM (crm)**.
   Больше ничего отмечать не нужно: сайту требуется только создание лидов.
6. Нажмите **Сохранить**.
7. Скопируйте строку из поля **Вебхук для вызова rest api**. Это и есть ваша ссылка.

Проверьте, что скопированная ссылка:

- начинается с `https://` и содержит домен вашего портала;
- содержит `/rest/`;
- заканчивается косой чертой `/`.

Если в конце черты нет — допишите её.

---

## Шаг 2. Добавить вебхук в Vercel

1. Откройте проект сайта на [vercel.com](https://vercel.com).
2. **Settings** → **Environment Variables**.
3. Нажмите **Add**, заполните:
   - **Key**: `BITRIX_WEBHOOK_URL`
   - **Value**: ссылка из шага 1
   - **Environments**: отметьте `Production`, `Preview` и `Development`
4. **Save**.
5. Откройте вкладку **Deployments** и нажмите **Redeploy** на последнем деплое.
   Переменные подхватываются только при сборке — без этого шага сайт продолжит
   работать со старыми настройками.

Готово. С этого момента все формы сайта создают лиды в Bitrix24.

### Остальные переменные

Они необязательные — со значениями по умолчанию всё работает. Полный список
с пояснениями лежит в [`.env.example`](../.env.example).

| Переменная | Зачем | По умолчанию |
| --- | --- | --- |
| `BITRIX_SOURCE_ID` | Источник лида в CRM | `WEB` |
| `BITRIX_ASSIGNED_BY_ID` | ID сотрудника-ответственного | распределяет Bitrix24 |
| `BITRIX_UTM_PRIORITY` | Какой источник в стандартные UTM-поля: `first` или `last` | `first` |
| `LEAD_RATE_LIMIT` | Лимит заявок с одного адреса, «сколько/за сколько секунд» | `10/60` |
| `LEAD_ALLOWED_ORIGINS` | Домены, с которых принимаются заявки | текущий домен сайта |

## Шаг 3. Проверить, что заявки доходят

1. Откройте сайт и отправьте тестовую заявку через форму «Заказать звонок».
2. В Bitrix24 откройте **CRM** → **Лиды**.
3. Должен появиться лид с названием вида
   **«Сайт | Общая заявка | Заказать звонок»**.
4. Откройте его и пролистайте до поля **Комментарий** — там весь контекст обращения.

Если лид не появился, откройте в Vercel **Deployments** → последний деплой →
**Runtime Logs** и найдите строку с `"event":"lead_failed"`. В ней будет код ошибки:

| Код | Что означает | Что делать |
| --- | --- | --- |
| `INVALID_CREDENTIALS`, `ACCESS_DENIED` | Вебхук неверный или у него нет прав на CRM | Пересоздать вебхук (шаг 1), отметив права **CRM** |
| `TIMEOUT`, `NETWORK_ERROR` | Портал не ответил вовремя | Обычно временно; проверьте доступность портала |
| `QUERY_LIMIT_EXCEEDED` | Слишком много обращений к порталу | Сайт повторит запрос сам; при постоянных ошибках поднимите лимиты в Bitrix24 |
| `not_configured` в ответе | Переменная `BITRIX_WEBHOOK_URL` не задана или задана с ошибкой | Проверьте шаг 2 и сделайте Redeploy |

Ни адрес вебхука, ни имя с телефоном в журнал не пишутся — только код формы,
город, ЖК и код ошибки.

## Шаг 4. Пользовательские поля (необязательно)

**Это можно не делать.** Сразу после шага 2 вся информация о заявке уже приходит
в карточку лида — в поле **Комментарий**, разбитая на разделы: контекст обращения,
ответы квиза, планировка, расчёт, страница, реклама, техническая информация.

Отдельные поля нужны, только если вы хотите **фильтровать и строить отчёты** по
конкретному значению — например, вывести все заявки с комнатностью «2 комнаты».

### Как создать поле

1. **CRM** → **Настройки** → **Настройки форм и отчётов** → **Пользовательские поля**.
2. Выберите раздел **Лид**, нажмите **Добавить поле**.
3. Тип — **Строка**, название — понятное, например `Код формы`.
4. Сохраните и откройте поле снова: в адресной строке или в свойствах будет виден
   его код вида `UF_CRM_1712345678`. Скопируйте его.

### Как подключить поле к сайту

Добавьте в Vercel (шаг 2) ещё одну переменную: имя из таблицы ниже, значение — код поля.

| Переменная | Что попадёт в поле |
| --- | --- |
| `BITRIX_UF_FORM_CODE` | Код формы, например `apartment_quiz` |
| `BITRIX_UF_FORM_TITLE` | Название формы |
| `BITRIX_UF_CITY` | Город |
| `BITRIX_UF_PROJECT` | ЖК |
| `BITRIX_UF_CTA_LOCATION` | Откуда нажали кнопку |
| `BITRIX_UF_PAGE_URL` | Адрес страницы |
| `BITRIX_UF_PAGE_TITLE` | Название страницы |
| `BITRIX_UF_LANG` | Язык сайта |
| `BITRIX_UF_SUBMISSION_ID` | Идентификатор отправки |
| `BITRIX_UF_FIRST_SOURCE` | Первый рекламный источник |
| `BITRIX_UF_LAST_SOURCE` | Последний рекламный источник |

Для отдельных ответов квиза, планировки и расчёта имя переменной строится как
`BITRIX_UF_DETAIL_` + ключ значения заглавными буквами:

| Переменная | Что попадёт в поле |
| --- | --- |
| `BITRIX_UF_DETAIL_QUIZ_ROOMS` | Комнатность из квиза |
| `BITRIX_UF_DETAIL_QUIZ_FLOOR` | Этаж из квиза |
| `BITRIX_UF_DETAIL_QUIZ_LAYOUT` | Планировка из квиза |
| `BITRIX_UF_DETAIL_QUIZ_PAYMENT` | Способ оплаты из квиза |
| `BITRIX_UF_DETAIL_LAYOUT_NAME` | Название планировки из popup |
| `BITRIX_UF_DETAIL_LAYOUT_AREA` | Площадь планировки |
| `BITRIX_UF_DETAIL_LAYOUT_PRICE` | Цена планировки |
| `BITRIX_UF_DETAIL_CALC_TOTAL` | Стоимость квартиры из калькулятора |
| `BITRIX_UF_DETAIL_CALC_MONTHLY` | Ежемесячный платёж |
| `BITRIX_UF_DETAIL_CALC_MODE` | Ипотека или рассрочка |

Полный список ключей — в исходном коде форм: они передаются первым элементом
в `buildDetails` (см. `src/components/**`).

Подключать поля можно по одному и в любой момент: пока переменной нет, значение
всё равно приходит в комментарий и не теряется.

## Что сайт делает, а что настраивается в Bitrix24

Сайт создаёт лид на начальной стадии и передаёт город. Всё дальнейшее —
распределение по сотрудникам, стадии, роботы, воронки и сделки — настраивается
средствами Bitrix24 и в задачу интеграции не входит.

Звонки и WhatsApp тоже остаются на стороне Bitrix24:

- клик по телефону лид не создаёт — звонок учитывает подключённая телефония;
- клик по WhatsApp лид не создаёт — сообщение обрабатывает открытая линия;
- исключение — формы «Получить каталог» и «Получить презентацию»: они сначала
  создают лид и только после подтверждения открывают WhatsApp с готовым текстом.
